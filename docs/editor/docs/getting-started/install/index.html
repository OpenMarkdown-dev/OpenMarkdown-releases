Install

npm 7 and later also install the editor's peer dependencies, CodeMirror and Lezer. With another package manager, or to pin them yourself, install them explicitly:

Why peers

Section titled “Why peers”

Your page must hold exactly one copy of @codemirror/state. Two copies break CodeMirror: extensions from one copy are not recognised by the other ("Unrecognized extension value"). Because CodeMirror is a peer, an app that already uses CodeMirror shares its copy with the editor.

What else comes with it

Section titled “What else comes with it”
  • temml (math) and mermaid (diagrams) are regular dependencies, declared as version ranges (mermaid ^11), so an app that already has a Mermaid 11 shares its copy. The editor loads them with import() only when a document contains math or a diagram, and your bundler splits them into separate chunks. A document without either never downloads them.
  • HTML inside Markdown is highlighted by @codemirror/lang-html, loaded the first time a document holds HTML; it is not part of the first load.
  • There is no CSS file to import. The editor injects its styles, and every color and font is a --ome-* custom property you can override (Theming).

Choose an entry

Section titled “Choose an entry”

The package has three entries with the same API. They differ only in the renderers they carry built in (math and diagram renderers):

Import Formulas Diagrams Use it when
@openmarkdown-dev/editor Temml, built in Mermaid, built in You want everything to work out of the box.
@openmarkdown-dev/editor/no-diagrams Temml, built in yours, or none No page needs diagrams, your page has its own Mermaid, or your style policy rules Mermaid out.
@openmarkdown-dev/editor/no-renderers yours, or none yours, or none Your page already renders math and diagrams (MathJax, KaTeX, Mermaid), or you bundle into one file.

Nothing /no-diagrams imports reaches Mermaid, and nothing /no-renderers imports reaches Temml or Mermaid, so your bundler emits no chunk for them, and a single-file (IIFE) bundle does not inline them (bundling into one file). npm still installs mermaid and temml, the main entry's dependencies.

Highlighted code blocks

Section titled “Highlighted code blocks”

Code blocks are highlighted when you opt in with codeLanguages. The usual list is @codemirror/language-data's (install it beside the editor; each language loads the first time a block uses it):

Without it, fenced code shows unhighlighted and none of the twenty-odd @codemirror/lang-* packages enter your lockfile.

Release-age gates

Section titled “Release-age gates”

Some projects refuse packages published in the last few days: bun's minimumReleaseAge (bunfig.toml), pnpm's minimumReleaseAge (pnpm-workspace.yaml), or a CI policy built on npm install --before. A version of the editor younger than that window is refused. Install the newest version older than your window rather than excluding the package from the gate:

Every release is listed with its date in the changelog, and its peers and dependencies are declared as ranges, so an older editor version installs with the CodeMirror your app already has.

No bundler?

Section titled “No bundler?”

Framework-free is not build-free. The package is ES modules with bare imports (@codemirror/state, …), which a browser cannot resolve on its own. A page without a bundler has two ways:

  • The prebuilt browser file, @openmarkdown-dev/editor/browser (dist/browser.js): one minified ES module with CodeMirror, Lezer and the formula renderer inside, for a <script type="module">. It is the /no-diagrams entry; for diagrams, give it your page's Mermaid (renderers). It cannot share CodeMirror with your page, so extensions built from another copy of CodeMirror do not work with it.
  • Your own build, served from your server: self-hosting gives the build script, for a server-rendered app with no bundler or a page that may not use a CDN.

Requirements

Section titled “Requirements”
  • The package is ES2022 JavaScript with TypeScript declarations included.
  • Importing it needs no DOM, so it is safe in server code (SSR). Mounting an editor needs a browser DOM.
  • Every build is tested by mounting, typing, rendering math and a diagram, and switching mode and scheme in headless Chromium, WebKit (Safari's engine) and Firefox.
