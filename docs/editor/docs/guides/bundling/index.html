Bundling into one file

Some hosts bundle everything into one script: an esbuild or Rollup build with format: "iife", a plugin system that loads one file, a template that has one <script> tag. A one-file build cannot leave anything for later, so every lazy import() in the editor is inlined into it: the formula renderer, Mermaid with all its diagram types, the HTML grammar. This page says what that costs for each entry and how to keep the file small.

If your bundler can split (Vite, webpack, Rollup or esbuild with format: "esm" and splitting: true), you need only first load with a splitting bundler: the renderers stay separate chunks, fetched only by a document that needs them.

What each entry inlines

Section titled “What each entry inlines”

Measured by the release check: one minified IIFE that mounts the editor, with CodeMirror and Lezer inside (your own copy of CodeMirror, if your page has one, is shared and not counted twice).

Import What is inlined besides the editor and CodeMirror Minified gzip
@openmarkdown-dev/editor Temml, Mermaid and every Mermaid diagram type, the HTML grammar 4270 KB 1214 KB
@openmarkdown-dev/editor/no-diagrams Temml, the HTML grammar 923 KB 304 KB
@openmarkdown-dev/editor/no-renderers the HTML grammar 721 KB 246 KB

The package's own code is the same in each. For a page that bundles into one file, use /no-renderers and give the editor the renderers your page already has, or /no-diagrams when the built-in formula renderer is welcome.

First load with a splitting bundler

Section titled “First load with a splitting bundler”

What a page loads before the editor appears, minified and gzipped with CodeMirror, is about the same for every entry, but not for every bundler:

Bundler First load Why
Vite, Rollup about 185 KB The HTML grammar is split out and loads the first time a document holds HTML.
esbuild (--bundle --splitting --format=esm --minify) about 250 KB @codemirror/lang-markdown imports @codemirror/lang-html at its top level and calls it there. esbuild keeps that call, so the HTML, CSS and JavaScript grammars land in the first load.

The esbuild figure is our measurement of a page that only mounts the editor (248 KB); an integration measured about 262 KB for its own page. Formulas and diagrams stay separate chunks with either bundler.

No bundler at all

Section titled “No bundler at all”

@openmarkdown-dev/editor/browser (dist/browser.js) is a prebuilt one-file ES module: the /no-diagrams entry with CodeMirror, Lezer, Temml and the HTML grammar inside, minified (about 304 KB gzipped), opening with the license notices of what it bundles. Load it with <script type="module"> from your own server or a CDN that serves npm files, and give it your page's Mermaid for diagrams. It holds its own CodeMirror, so it cannot take extensions built from another copy; a page that uses CodeMirror itself should bundle the package instead (self-hosting).

It exports the editor's functions only, not CodeMirror's LanguageDescription, so it cannot take codeLanguages either: fenced code shows unhighlighted. For highlighted code blocks, bundle the package with the languages you want (the recipe in code blocks above).
