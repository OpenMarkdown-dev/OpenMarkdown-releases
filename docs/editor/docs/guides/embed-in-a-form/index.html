Embed in a form or CMS field

A Markdown field in a form, a CMS entry or a settings page differs from a full-page editor in a few ways: it grows with its text, it has a label, its value is a string, it may be read-only, and there is no file path to store pasted images beside. Each has an option.

A complete field

Section titled “A complete field”

Style the field through .ome-root, never .cm-editor: a table cell being edited is an editor of its own (.ome-nested), and a rule on .cm-editor would reach it too. To take the page's font, size and color, use the "Fit the host page" recipe in Theming.

Height

Section titled “Height”

height: "auto" makes the editor as tall as its content, with the bottom space the same as the top (--ome-padding-y) instead of the room a full-page editor leaves to scroll past the end. A min-height on .ome-root keeps an empty field from collapsing, and a click in the blank below the text puts the caret at the end. The default, "fill", takes the parent's height and scrolls inside it. See Theming.

Label, name and focus

Section titled “Label, name and focus”

The editable text is a contenteditable element, not a form control, so a browser does not connect it to a <label> by itself:

  • id puts the id on the editable text, and a click on a <label for> with that id focuses the editor.
  • ariaLabelledBy (an element's id) or ariaLabel (a string) gives the field its accessible name. A <label for> alone does not name it for screen readers.
  • editor.focus() gives it the keyboard focus, for example when a form shows a validation error.

The value is a string

Section titled “The value is a string”

openMarkdownText and saveMarkdownText are the string form of the file codec: unedited, the string you saved is the string you loaded, exactly; edited, it keeps the original BOM and line endings. editor.isUnedited(file) answers "are there unsaved changes?" with the same test. If you decode bytes yourself, decode with TextDecoder("utf-8", { ignoreBOM: true }) (a default decoder drops the BOM before the codec sees it), or pass the bytes to openMarkdownFile.

After a save, make what you saved the new baseline (file = openMarkdownText(saved)), so that isUnedited means "unsaved since the last save".

Read-only

Section titled “Read-only”

editable: false makes the field read-only in every mode: no typing, pasting, dropping, checkbox ticking or property editing, and no editing controls are drawn. The reader can still select, copy, search and follow links. Switch it with editor.setEditable(true | false), for example while the form is submitting. Reading mode (mode: "reading") is a different thing: a rendered view that still lets the reader tick a task checkbox.

Images without a file path

Section titled “Images without a file path”

A CMS entry has no path, so saveAttachment (which stores an image beside the document) does not apply. uploadImage(bytes, hint) stores the image wherever you keep images and resolves the link target, or null when the upload failed. See Images.

Several fields on one page

Section titled “Several fields on one page”

Each editor has its own options. Give one field its own color scheme, link policy or key bindings with environment, and change them with editor.setEnvironment; the page defaults from configureEditorEnvironment fill in what a field does not give. See the environment.

Commands for a toolbar

Section titled “Commands for a toolbar”

A field's own toolbar can call the editor's commands on the handle, with no import from the CodeMirror packages: editor.undo(), editor.redo(), editor.openSearch(), editor.closeSearch(), editor.isSearchOpen(), editor.revealText(text) (select a passage and scroll to it) and editor.focus(). editor.view is the CodeMirror view, for anything else.

Class components and other lifecycles

Section titled “Class components and other lifecycles”

The editor needs only a mount point and a cleanup. In a React class component, mount in componentDidMount, call editor.destroy() in componentWillUnmount, and push outside value changes in componentDidUpdate with editor.setDoc(value) when it differs from editor.getDoc(). The same three steps fit any framework; see Use it in any framework.

Replacing a CodeMirror editor you already have

Section titled “Replacing a CodeMirror editor you already have”

If the field was a plain CodeMirror 6 editor, pass its state as fromState. The new editor takes its document, selection and undo history, so Mod+Z still undoes what the user typed before the switch:

The history carries over only when both editors use the same copy of @codemirror/commands (it is a peer dependency, so one copy is the normal case). Nothing else of the old state comes along: its extensions, keymaps and listeners are its own. Pass your own extensions again with extensions, which takes one extension or an array.
